# DESIGN BLUEPRINT — SatQuery AI

## DESIGN NORTH STAR
SatQuery AI is a viewport to the Earth, controlled by intention. Every interface element that is not the map must actively help spatial discovery, investigation, or quantitative understanding. The interface is not a dashboard. The interface is not a chatbot. The interface is not an AI command center. The map is the product. Natural language is the control layer.

---

## SECTION 1 — PRODUCT UI ARCHITECTURE

The application hierarchy progressively discloses information to maintain maximum map visibility.

1. **Application Shell (Persistent):** The absolute minimum framing required to orient the user.
2. **Map Workspace (Persistent):** The `z-index: 0` layer containing the geographic context. Always 100% viewport.
3. **Spatial Controls (Contextual):** Base map controls (zoom, layers, crosshairs) that fade or minimize when not in use.
4. **Query Layer (Contextual):** The floating natural-language control palette. Prominent when idle, minimizes when analyzing.
5. **Analysis State (Transient):** Minimal progress indication tied to the query layer. No raw logs.
6. **Spatial Results (Contextual):** Geographic masks (polygons, bounding boxes) overlaid directly on the map.
7. **Evidence (Progressive):** Concise text answers and key metrics anchored geographically to the results.
8. **Region Investigation (Progressive):** A side sheet for deep quantitative exploration (histograms, timelines).
9. **Deep Technical Details (Buried):** Telemetry (EPSG, GSD) tucked into a minimal footer or accessible via a settings icon.

---

## SECTION 2 — APPLICATION SHELL

The permanent shell is almost invisible. It exists only to frame the workspace.

*   **Header:** A minimal, transparent top bar.
    *   *Left:* Subtle SatQuery wordmark (not a glowing logo).
    *   *Right:* Global actions (Report Export, User Settings).
*   **Map Viewport:** Fills the entire screen beneath the transparent header.
*   **Status Information:** A tiny, monospaced text string at the bottom-right showing current EPSG code and Lat/Lon of cursor.

**Rule:** No opaque sidebars, no multi-panel grids, no thick borders around the edge of the screen.

---

## SECTION 3 — MAP WORKSPACE

The map is the primary interactive surface.

*   **Layer Controls:** A small, collapsable floating action button (FAB) group in the bottom-left. Expands to a clean list of base layers (Optical, SAR) and analysis layers (Change, Masks).
*   **Navigation:** Map handles its own pan/zoom natively (scroll/drag). Optional subtle zoom `+`/`-` buttons in the bottom-right above coordinates.
*   **Geographic Selection:** The user can drop pins or draw bounding boxes directly on the canvas using cursor tools, which activates the Query Layer with spatial context.
*   **Overlays:** Raster and vector overlays generated by the backend are injected into the map's layer stack, ensuring they scale and pan with the geography.

---

## SECTION 4 — QUERY CONTROL LAYER

The primary interaction vector. It behaves like a spotlight search or command palette.

*   **A. First Visit:** The map loads a stunning, high-res default location. The query palette sits prominently in the bottom-center of the screen, open and pulsing subtly. A placeholder reads: "Press Cmd+K or type to investigate this region..."
*   **B. Idle:** The palette rests as a compact search bar at the bottom-center.
*   **C. Query Active:** When focused, the palette elevates slightly. A small dropdown appears below it offering suggested queries based on the current geographic features (e.g., "Find water bodies", "Detect recent changes").
*   **D. Query Submitted:** The input text turns into an immutable "pill" block. The input field closes.
*   **E. Analysis Running:** The pill displays a meaningful, human-readable state (see Section 5). A subtle linear progress bar moves across the bottom edge of the pill.
*   **F. Results Available:** The pill expands into a small floating card containing the primary text answer and 1-3 key metrics. The map simultaneously snaps to show the spatial overlay.
*   **G. Minimized:** If the user clicks away or starts panning, the result card shrinks back to a compact tab or icon anchored to the side of the screen, allowing full map view.

**Keyboard Behavior:** `Cmd+K` (or `Ctrl+K`) universally focuses the query input, regardless of current state. `Esc` clears or minimizes the active query.

---

## SECTION 5 — ANALYSIS STATE SYSTEM

Transparency without architecture exposition. We communicate intent, not backend topology.

**Allowed States (Meaningful):**
1.  *Understanding question...* (Routing)
2.  *Preparing satellite imagery...* (Fetching/Validating data)
3.  *Scanning region for [Feature]...* (Model inference)
4.  *Calculating spatial metrics...* (Post-processing)
5.  *Rendering evidence...* (Result generation)

**Banned States:**
*   *Booting Agent_004...*
*   *Loading PEFT weights...*
*   *Trace: {"status": 200, "model": "resnet50"}*

---

## SECTION 6 — RESULTS ARCHITECTURE

Results are anchored to the geography, not a separate dashboard.

1.  **Primary Answer:** A concise sentence in the floating Result Card (e.g., "14 new structures detected since April 2023.").
2.  **Spatial Findings:** Polygons drawn directly on the map.
3.  **Quantitative Metrics:** Key numbers (`14 structures`, `2.4 sq km`) displayed as chips inside the Result Card.
4.  **Before/After Imagery:** Controlled via a vertical slider that appears over the map itself, allowing the user to swipe between T1 and T2 directly on the geographic canvas.

---

## SECTION 7 — REGION INVESTIGATION

Deep dives happen in a progressive side sheet.

*   **Trigger:** Clicking on a highlighted spatial region (e.g., a specific drawn polygon) or clicking "Deep Inspect" on the Result Card.
*   **Action:** A side sheet slides out from the right edge of the screen (occupying max 30% width). The map automatically offsets its center so the selected region is not obscured by the sheet.
*   **Content:** Detailed histograms, pixel-intensity graphs, temporal trend lines, and confidence scores for that specific polygon.
*   **Dismissal:** Clicking the map or pressing `Esc` immediately slides the sheet away.

---

## SECTION 8 — DESIGN SYSTEM

Visual restraint is paramount. No trend-chasing.

### A. Typography
*   **Primary (UI):** Inter (Clean, highly legible at small sizes).
*   **Numeric & Metadata:** IBM Plex Mono (Perfect for coordinates, EPSG codes, and raw data).
*   **Hierarchy:**
    *   H1: 18px Inter SemiBold (Result titles)
    *   Body: 14px Inter Regular (Primary text, query input)
    *   Caption: 12px Inter Medium (Labels, button text)
    *   Metadata: 11px IBM Plex Mono (Coordinates, technical specs)

### B. Spacing
*   Base unit: 4px.
*   Dense interface logic. Elements inside panels use 8px/12px padding. Distance between floating panels and screen edges is 24px.

### C. Radius
*   Extremely restrained.
*   **Panels/Cards:** 4px radius (sharp, professional, instrument-like).
*   **Pills/Badges:** 2px radius.
*   **Banned:** Fully rounded capsule shapes (e.g., 9999px radius on search bars) unless explicitly used for a floating FAB button.

### D. Borders
*   Used strictly to separate surfaces in dark mode.
*   Opacity: Very low (`rgba(255, 255, 255, 0.1)`).
*   Style: 1px solid.
*   **Banned:** Thick borders, colored borders, "accent side-borders" on cards.

### E. Surfaces
Avoid arbitrary floating glass everywhere.
*   **Base:** The map.
*   **Floating Control Surface (Query Palette):** Solid dark gray (`#1C1C1C`) with a very subtle background blur (`backdrop-filter: blur(8px)`) and a `0.6` opacity fill to allow faint map texture through while guaranteeing text contrast.
*   **Investigation Surface (Side Sheet):** Solid opaque dark gray (`#121212`) to ensure complex charts render perfectly.
*   **Transient Feedback (Tooltips):** Solid black (`#000000`).

### F. Shadows
*   Elevation is built with neutral, multi-layered drop shadows.
*   *Floating Panels:* `box-shadow: 0 8px 32px rgba(0,0,0,0.4), 0 1px 2px rgba(0,0,0,0.2)`.
*   **Banned:** Colored glow (no cyan drop shadows).

### G. Colors
1.  **Neutral Interface:**
    *   Backgrounds: `#121212`, `#1C1C1C`, `#262626`
2.  **Text Hierarchy:**
    *   Primary: `#FFFFFF`
    *   Secondary: `#A1A1AA` (Zinc 400)
    *   Disabled: `#52525B` (Zinc 600)
3.  **Interactive States:**
    *   Focus ring: `#FFFFFF` (2px solid outline)
4.  **Semantic Geospatial Data (DO NOT USE FOR UI CHROME):**
    *   *Water / Hydrology:* `#3B82F6` (Blue)
    *   *Vegetation / Biomass:* `#22C55E` (Green)
    *   *Built-up / Urban:* `#F59E0B` (Amber)
    *   *Change / Alert:* `#EF4444` (Red)
    *   *Selected Region:* `#D946EF` (Fuchsia outline)

## SECTION 9 — COMPONENT SYSTEM

*   `IconButton`: 32x32px, 4px radius, monochromatic icon, subtle gray hover state. Used for map controls.
*   `QuerySurface`: The main command palette. Contains an input field and houses the analysis states.
*   `AnalysisStatePill`: A compact indicator for meaningful progress.
*   `SpatialResultCard`: The floating answer container. 4px radius, 1px subtle border. Contains the primary text and metric chips.
*   `MetricChip`: Used inside results. IBM Plex Mono number + Inter label. (e.g., `[ 2.4 sq km | Water ]`).
*   `RegionSheet`: The sliding right-panel. Fixed width, scrollable interior, opaque background.

---

## SECTION 10 — LANDING PAGE

*   **Concept:** "The Earth is waiting."
*   **Interaction (Three.js):** A high-fidelity, interactive 3D globe rendered against a true-black void. Users can drag to rotate.
*   **Entry:** A single, centered query input (identical to the `QuerySurface` in the app) hovers over the globe. "What do you want to investigate?"
*   **Transition:** Upon submitting a location or query, the 3D globe smoothly rotates and zooms into the target coordinates, blending seamlessly into the 2D mapping workspace as the UI shell fades in.
*   **Requirement:** The typography, colors, and input component on the landing page must be identical to the main application. No separate visual identities.

---

## SECTION 11 — RESPONSIVE STRATEGY

*   **Desktop (Primary):** Floating query palette bottom-center. Side sheet opens on the right. Map controls bottom-left.
*   **Tablet:** Query palette becomes full-width at the very bottom edge. Side sheet behaves as a modal overlay rather than a push-panel.
*   **Mobile:**
    *   The map is still 100%.
    *   Query input is anchored to the bottom edge.
    *   Deep Investigation (Side Sheet) becomes a bottom-sheet that drags up over the map.
    *   Hover interactions must be mapped to tap-to-select.

---

## SECTION 12 — AI-SLOP GUARDRAILS

*   **REJECT: Excessive rounded cards.** *Why:* Bubbly, pill-shaped UI looks like a consumer toy. Geospatial tools need to feel precise and sharp. 4px is the maximum radius for panels.
*   **REJECT: Floating glass everywhere.** *Why:* Glassmorphism reduces text contrast and creates visual noise. Use it only for the `QuerySurface` to maintain context; solid colors elsewhere.
*   **REJECT: Decorative grid backgrounds.** *Why:* The map provides all the grid and texture needed. A grid on the UI is distracting terminal cosplay.
*   **REJECT: Glowing shadows (`box-shadow: 0 0 10px cyan`).** *Why:* It's the hallmark of cheap "cyberpunk AI" design. Shadows must be black/neutral to convey physical depth.
*   **REJECT: Meaningless status dots / typing text.** *Why:* Power users hate waiting for cinematic typewriter effects. Show the data instantly.
*   **REJECT: Dashboard metric-card grids.** *Why:* Forces the map into a tiny widget. Metrics must overlay the map or live in the collapsible side-sheet.
*   **REJECT: Generic Space Grotesk / Startup typography.** *Why:* This is a technical instrument, not a SaaS marketing site. Inter + Plex Mono ensures credibility.

## SECTION 13 — IMPLEMENTATION ARCHITECTURE

**Current State (`index.html` monolith):**
*   *Delete:* `genScene()`, `noiseGrid()`, `renderOptical()`, `renderSAR()` (Procedural canvas hacks).
*   *Delete:* The entire 3-column CSS grid layout (`.wrap`).
*   *Delete:* All fake LEDs, scanlines, and hacker panels.
*   *Preserve:* `runQuery()` state logic (to be adapted).
*   *Preserve:* Backend FastAPI contracts (`POST /analyze`).

**New Architecture:**
*   *Create:* A modern frontend build setup (e.g., Vite + React/Vanilla JS components).
*   *Create:* A real mapping library integration (e.g., Leaflet or Mapbox GL JS) to replace the raw Canvas procedural drawing.
*   *Create:* The `QuerySurface` component.
*   *Integration:* The frontend must construct `multipart/form-data` requests matching the existing FastAPI validator. The `registry.py` stubs remain untouched (they will still return `NotTrainedYet`, but the UI must gracefully handle this simulated response without breaking).

---

## SECTION 14 — IMPLEMENTATION ORDER

**PHASE 1: Architectural Foundation**
*   *Goal:* Scaffold the new frontend, integrate the real map library, and connect to the existing FastAPI backend.
*   *Validation:* Map loads, `POST /analyze` successfully hits the backend and returns the stubbed response.

**PHASE 2: Application Shell & Map Workspace**
*   *Goal:* Implement the 100% viewport map, minimal header, and map controls (zoom/layers).
*   *Validation:* Map is full screen; no console errors; clean styling.

**PHASE 3: Query Control Layer**
*   *Goal:* Build the `QuerySurface` command palette with `Cmd+K` support and idle/active states.
*   *Validation:* User can type a query, submit it, and the UI transitions to a loading state.

**PHASE 4: Analysis State & Results Architecture**
*   *Goal:* Connect the query submission to the backend response. Display the `SpatialResultCard` and draw basic polygons on the map.
*   *Validation:* Text results appear in the floating card; map renders a vector overlay.

**PHASE 5: Region Investigation (Deep Dive)**
*   *Goal:* Implement the progressive disclosure side-sheet triggered by clicking a map overlay.
*   *Validation:* Sheet slides out cleanly without breaking map view.

**PHASE 6: Polish & Motion**
*   *Goal:* Apply final Impeccable critique. Ensure shadows, typography (Inter/Plex), and transitions are flawless. Verify contrast.
*   *Validation:* No AI-slop violations.

*(Note: Landing Page Three.js integration is deferred to a future phase once the core application is flawless).*
